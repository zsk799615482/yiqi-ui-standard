# 导航组件统一调用

## 入口与意图

使用 `$yiqi-ui-standard` 加自然语言；目录 ID 是内部稳定标识，用户不必记忆。

| 请求示例 | 执行范围 |
|---|---|
| 为当前 React 项目选悬浮导航，先推荐 | 读取相关目录并给一个任务级首选，不改业务代码 |
| 对比 Pill Nav 和 Morphic Navbar | 对比用户点名项；比较任务不受“单一推荐”限制 |
| 单独预览 Vue Bits Staggered Menu | 在已有授权的独立预览位置生成，不替换生产路由；没有位置时选择项目隔离输出目录并说明 |
| 使用 Vue Bits Staggered Menu 替换当前侧栏 | 检查来源、项目与依赖，执行明确替换范围，保留路由、权限与业务入口 |
| 手机端用 Konsta Tabbar，桌面不变 | 按栈选择 React 或 Vue 版，只处理移动底栏 |

这是由代理执行的指导流程，不是现有 Showcase 解析器的新参数。没有新增自动下载、安装或无条件生成命令。

## 按需加载

| 导航职责 | 目录 | 配方 |
|---|---|---|
| 顶部主导航 | `top-navigation-catalog.json` | 已有 `17-top-dock.md` 或对应条目的 brandRecipe |
| 悬浮胶囊、Dock、滚动变形、创意导航 | `floating-navigation-catalog.json` | `floating-navigation-recipes.md` 中对应锚点 |
| 常驻侧栏、抽屉、侧向覆盖菜单 | `sidebar-navigation-catalog.json` | `sidebar-navigation-recipes.md` 中对应锚点 |
| 移动端底部导航 | `mobile-navigation-catalog.json` | `mobile-navigation-recipes.md` |

先读取本文件和相关目录，选定后才加载配方。不要默认加载全部来源或整站文档。任务阶段沿用用户表述；选型不强制询问工程技术栈，已知栈用于过滤，实现前才必须确认栈。

## 决策优先级

1. 识别页面任务、导航职责、桌面／移动作用域。全局导航、章节定位、工具操作和覆盖菜单不能仅按外观互换。
2. 没有替换要求时优先保留已批准等价导航；用户明确替换或点名新来源时，以当前要求为准。
3. 明确来源优先于品牌默认，但仍检查栈、能力、版本、授权与现有依赖。名称跨栈歧义优先按项目栈解决。
4. 未点名时，按任务适配、已有依赖、实施成熟度及取用条件提出一个首选。悬浮、侧边、移动端的目录 `defaultFor` 永远为 `none`，单次推荐不能回写成全局默认。Konsta 是当前移动候选，不是品牌默认。
5. 顶部仍仅在 OneSeven、页面确需顶部主导航且无已批准等价方案时使用 17 Top-dock 默认。不能因其他类别没有默认而用它代替。
6. 不支持目标栈、只有视觉参考、区块未确定时，输出缺口及下一步，不伪造可用模板、不静默移植或换源。无适配项时保留现有导航或提出明确的适配方案。

桌面和移动可以选不同来源，但共享导航数据：稳定键、文本、目标路由、权限可见性、当前页状态。不要把 Hover Dock 原样放到触屏；不要默认叠放两个承担同一主任务的导航。

## 来源状态与实施规则

三份新增目录以 `source-recipe`（来源配方）、`block-collection`（待具体化区块集）、`visual-reference`（视觉参考）收录研究结果；`verificationStatus` 表示核验程度，不是许可批准。只有实际附带且验收过的本地模板才可用 `internal-template`。目录时间是研究快照，`sourceVersion: null` 表示尚未锁定取用版本。

实施前从官方来源锁定具体组件、版本或 commit，核查文件许可、依赖和项目使用方式；完整支持 React/Vue 不等于 Next/Nuxt SSR 已通过。保留来源、版权和归属。Skill 只收录原创指导与来源索引，不打包第三方源码。

依赖沿用 `library-selection.md`，效果沿用 `showcase-mode.md` / `animation-craft.md`；已有同范围授权直接复用，不重复询问。指定组件不是新增依赖安装或商业内容购买的自动授权；仍遵守任务授权和现有依赖规则。

标准模式下若指定组件依赖现有限制不允许加载的高级运行时，说明冲突和可选方案，不能默默切展示模式或引入依赖。来源自带玻璃时先评估自身实现，不因“玻璃”一词再叠加 GlassSurface。采用独立玻璃来源才进入对应材质流程。

导航配方决定胶囊、Dock 和底栏几何；卡片的 36px 规则不直接套到导航。尊重当前项目主题，不自动增加顶部 Logo、滚动隐藏或弹簧；用户对 17 Top-dock 的要求不自动推广到其他类别。

## 输出与项目记录

选型输出：使用意图、目标范围、选中名称／ID、选中理由、适配缺口及取用方式。明确指定且上下文完整的实现任务直接继续，不重复要求确认同一提案；新范围或无法解决的来源缺口才提问。

实施后更新业务项目已有的 UI 规范／组件记录；没有适合位置时写入 `docs/ui/navigation.md`。按桌面／移动作用域记录：

- 类别、职责、目录 ID、具体区块（如适用）。
- 官方来源、实际版本／commit、文件与许可核验、已授权范围。
- 路由绑定、主题、断点、依赖、材质与降级选择。
- 实际修改位置、执行过的验收、未验证的平台和剩余限制。

这是实际取用记录，不在只推荐时写成“已实现”，也不需要再造一套包锁文件。

## 验收

实施按所选配方检查路由选中、键盘／触屏、菜单关闭和焦点、深浅色、宽度与安全区、减少动态及项目需要的 SSR。静态目录检查只证明引用和元数据正确；不证明代理自动选型、浏览器视觉或产品功能已通过。
