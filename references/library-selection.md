# 通用工程库选择

本文档把 `pick-ui-library` 的依赖决策方法内化到 Yiqi。它只处理完成产品功能所需的通用工程库，不处理 Showcase 的 3D、液态玻璃、滚动叙事和高级视觉来源。

## 何时执行

只在代码实现阶段、确认技术栈之后执行。规划阶段只记录“需要 Toast / 图表 / 拖拽”等能力，不提前锁定包名；审查阶段先识别现有依赖，再判断是否存在重复或不必要的库。

## 决策顺序

```text
识别功能任务
→ 检查 package.json 与已有设计系统
→ 判断原生能力是否足够
→ 过滤技术栈不匹配项
→ 检查无障碍、性能、SSR/移动端和许可证
→ 只给一个首选方案
→ 说明不迁移理由和回退方案
→ 用户明确要求时才安装或修改依赖
```

## 硬规则

1. 先解决任务，不盲从用户指定的库；用户指定的库仍需检查是否适合当前任务。
2. 项目已有等价依赖时，不主动迁移、替换或并存重复库。
3. 原生 HTML、CSS 或浏览器 API 足够时，不新增依赖。
4. 推荐一个首选方案，不输出没有判断依据的库清单。
5. 版本、许可证和维护状态必须在实际实现时重新核验；目录中的版本只是参考快照。
6. 第三方库只提供行为、算法或运行时；视觉必须映射到项目现有设计系统和 OneSeven Token。
7. 未明确许可证、技术栈不匹配或无法提供回退时，不进入自动推荐。
8. 推荐不会自动执行 `npm install`、升级、卸载或锁文件改写；这些操作需要用户明确要求。

## 推荐输出

```markdown
## 依赖选择

### 功能任务
需要实现可筛选、可排序的数据表。

### 当前项目检查
项目已经使用现有表格方案，不增加新的表格依赖。

### 推荐方案
继续使用现有方案。

### 选择理由
已有依赖满足需求，避免重复库、迁移成本和样式冲突。

### 回退方案
简单数据量使用原生 HTML table；数据量增长后再评估虚拟化。
```

没有现有方案时，必须补充：推荐库、用途、支持技术栈、许可证、性能与包体积、SSR/移动端/无障碍风险、未选择其他方案的原因和无库回退。

## 与 Showcase 的边界

| 目录 | 管理内容 | 示例 |
| --- | --- | --- |
| `library-catalog.json` | 通用工程能力 | Toast、Dialog、Chart、Virtualization、State |
| `showcase-catalog.json` | 高级视觉与展示运行时 | Motion、Three.js、Liquid Glass、GSAP |

Standard 页面不得因通用库选择而加载 Showcase 重型依赖；Showcase 页面也必须先判断产品任务，再决定是否需要高级效果。

## OneSeven 适配

- 组件库默认主题、颜色、圆角、字体和 Demo 文案不得直接进入业务页面。
- 行为 Primitive 需要重新绑定 OneSeven Token、焦点状态、密度和卡片材质。
- 所有新增库都必须保持暗色默认、Alibaba PuHuiTi、状态不只依赖颜色以及移动端可用性。
- 高密度工作台优先保证可扫描、可键盘操作和空间效率，不为装饰增加依赖。
